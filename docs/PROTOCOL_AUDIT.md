## Protocol scope

2026-07-28 core synchronous discovery/tool/resource/prompt/completion requests are supported. Legacy initialization sessions support 2025-11-25, 2025-06-18, and 2025-03-26. Session state is an application compatibility wrapper around the stateless SDK service, not a modern requirement.

Modern per-request processes eliminate authenticated-user state reuse and recover after upstream crashes. They discard upstream in-memory history between calls and incur process startup and initialization on each operation, including list requests. Stateful tools requiring cross-call continuity (for example Sequential Thinking) are not compatible with this modern path; disk-backed operations can persist data independently of the child. Legacy sessions reuse one child to preserve intentional session state, bound to the mount and authenticated subject. No authorization headers, access tokens, session IDs, or Basic credentials enter stdio parameters/environment.

Tasks, subscriptions/resumption, MRTR interactive continuations, sampling/elicitation callbacks, logging, and MCP Apps are unsupported and unadvertised. Trace/custom `_meta` fields are preserved; modern protocol-specific capability declarations are removed before legacy dispatch. SDK-generated cache hints are private, avoiding a cross-principal public cache claim.

Full fixture conformance includes interactive and optional extension operations. A failed full run is retained and reported even when those operations are outside advertised capability. Applicable subsets are separately selected by supported behavior; they are never labeled full conformance certification.
