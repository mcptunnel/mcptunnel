# v0.3.5 — authenticated legacy cancellation

Legacy cancellation notifications now reach an active stdio request in the same mount and authenticated session. Typed request IDs prevent numeric/string collisions, duplicate active IDs fail without replacing state, and response completion/disconnect releases reservations. Cancellation remains available when ordinary mount/session call slots are occupied. The global HTTP request limit still applies.

Three focused legacy gateway tests passed with real HTTP and stdio processes: cancellation, session/principal/mount isolation, typed IDs, malformed transport rejection, duplicate/reused IDs and child cleanup. Tracked in [td#601](https://tdtd.dev/601). Unpublished.
